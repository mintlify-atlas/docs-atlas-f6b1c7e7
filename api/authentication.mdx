title: "Autenticación de la API con Tokens Bearer"
description: "Cómo registrarse, iniciar sesión y autenticar solicitudes a la API de ViniHotel usando tokens JWT Bearer con expiración de 7 días y control de acceso basado en roles."
---

La API de ViniHotel usa JSON Web Tokens (JWT) para la autenticación. Tras registrarse o iniciar sesión, el servidor devuelve un token firmado que debe incluirse como token Bearer en el encabezado `Authorization` de cada solicitud protegida. Los tokens expiran tras 7 días y codifican el ID y el rol del usuario (`client`, `staff` o `admin`).

## Registro

Crea una nueva cuenta de usuario con el rol `client` y devuelve un token JWT listo para usar de inmediato.

**`POST /api/auth/register`**

### Cuerpo de la solicitud

<ParamField body="nombre" type="string" required>
  Nombre del usuario.
</ParamField>

<ParamField body="apellido" type="string" required>
  Apellido del usuario.
</ParamField>

<ParamField body="email" type="string" required>
  Dirección de correo electrónico única. Devuelve `400` si la dirección ya está registrada.
</ParamField>

<ParamField body="contrasena" type="string" required>
  Contraseña en texto plano (mínimo 6 caracteres). Se almacena como hash bcrypt — nunca persiste en texto plano.
</ParamField>

<ParamField body="phone" type="string">
  Número de teléfono de contacto.
</ParamField>

<ParamField body="address" type="string">
  Dirección postal o de calle.
</ParamField>

<ParamField body="nationality" type="string">
  Nacionalidad del usuario.
</ParamField>

<ParamField body="documentId" type="string">
  Número de pasaporte o identificación nacional.
</ParamField>

### Respuesta

<ResponseField name="message" type="string">
  Cadena de confirmación: `"Usuario registrado exitosamente"`.
</ResponseField>

<ResponseField name="token" type="string">
  Token JWT Bearer firmado, válido por 7 días.
</ResponseField>

<ResponseField name="user" type="object">
  Subconjunto del registro del usuario recién creado.

  <Expandable title="campos de user">
    <ResponseField name="idUsuario" type="integer">
      Clave primaria auto-incrementada de la tabla `usuarios`.
    </ResponseField>

    <ResponseField name="nombre" type="string">
      Nombre.
    </ResponseField>

    <ResponseField name="apellido" type="string">
      Apellido.
    </ResponseField>

    <ResponseField name="email" type="string">
      Dirección de correo electrónico.
    </ResponseField>

    <ResponseField name="rol" type="string">
      Siempre `"client"` para el auto-registro.
    </ResponseField>
  </Expandable>
</ResponseField>

### Ejemplo

<CodeGroup>

```bash cURL
curl -X POST http://localhost:5000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"nombre":"Juan","apellido":"Perez","email":"juan@example.com","contrasena":"password123"}'
```

```json Response
{
  "message": "Usuario registrado exitosamente",
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": {
    "idUsuario": 1,
    "nombre": "Juan",
    "apellido": "Perez",
    "email": "juan@example.com",
    "rol": "client"
  }
}
```

</CodeGroup>

## Inicio de sesión

Autentica a un usuario existente mediante correo electrónico y contraseña, y devuelve un nuevo token JWT.

**`POST /api/auth/login`**

### Cuerpo de la solicitud

<ParamField body="email" type="string" required>
  Dirección de correo electrónico registrada.
</ParamField>

<ParamField body="contrasena" type="string" required>
  Contraseña de la cuenta. Nota el nombre del campo en español — `contrasena`, no `password`.
</ParamField>

### Respuesta

<ResponseField name="message" type="string">
  Cadena de confirmación: `"Login exitoso"`.
</ResponseField>

<ResponseField name="token" type="string">
  Token JWT Bearer firmado, válido por 7 días.
</ResponseField>

<ResponseField name="user" type="object">
  Campos principales del usuario: `idUsuario`, `nombre`, `apellido`, `email`, `rol`.
</ResponseField>

### Ejemplo

<CodeGroup>

```bash cURL
curl -X POST http://localhost:5000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"juan@example.com","contrasena":"password123"}'
```

```json Response
{
  "message": "Login exitoso",
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": {
    "idUsuario": 1,
    "nombre": "Juan",
    "apellido": "Perez",
    "email": "juan@example.com",
    "rol": "client"
  }
}
```

</CodeGroup>

<Warning>
  Tanto el registro como el inicio de sesión devuelven un error genérico `401` (`"Email o contraseña incorrectos"`) cuando las credenciales son incorrectas, sin revelar cuál campo falló, para prevenir la enumeración de usuarios.
</Warning>

## Obtener usuario actual

Devuelve el perfil completo del usuario autenticado, incluyendo los campos opcionales establecidos en el registro o mediante la actualización del perfil.

**`GET /api/auth/me`** — requiere `Authorization: Bearer <token>`

### Respuesta

<ResponseField name="idUsuario" type="integer">
  Clave primaria del usuario.
</ResponseField>

<ResponseField name="nombre" type="string">
  Nombre.
</ResponseField>

<ResponseField name="apellido" type="string">
  Apellido.
</ResponseField>

<ResponseField name="email" type="string">
  Dirección de correo electrónico.
</ResponseField>

<ResponseField name="rol" type="string">
  Rol: `client`, `staff` o `admin`.
</ResponseField>

<ResponseField name="phone" type="string">
  Número de teléfono de contacto, si está configurado.
</ResponseField>

<ResponseField name="address" type="string">
  Dirección, si está configurada.
</ResponseField>

<ResponseField name="dateOfBirth" type="string">
  Fecha de nacimiento, si está configurada.
</ResponseField>

<ResponseField name="nationality" type="string">
  Nacionalidad, si está configurada.
</ResponseField>

<ResponseField name="documentId" type="string">
  Número de pasaporte o identificación nacional, si está configurado.
</ResponseField>

### Ejemplo

<CodeGroup>

```bash cURL
curl -H "Authorization: Bearer YOUR_TOKEN_HERE" \
```

```json Response

  "address": null,

```

</CodeGroup>

## Actualizar perfil

Actualiza los campos modificables de la cuenta del usuario autenticado. Los campos `email`, `rol` y `contrasena` no pueden cambiarse a través de este endpoint.

**`PUT /api/auth/profile`** — requiere `Authorization: Bearer <token>`

### Cuerpo de la solicitud

Envía cualquier subconjunto de los siguientes campos; los campos omitidos se establecen en `null` en la base de datos.

<ParamField body="nombre" type="string">
  Nombre actualizado.
</ParamField>

<ParamField body="apellido" type="string">
  Apellido actualizado.
</ParamField>

<ParamField body="phone" type="string">
  Número de teléfono actualizado.
</ParamField>

<ParamField body="address" type="string">
  Dirección actualizada.
</ParamField>

<ParamField body="dateOfBirth" type="string">
  Fecha de nacimiento actualizada.
</ParamField>

<ParamField body="nationality" type="string">
  Nacionalidad actualizada.
</ParamField>

<ParamField body="documentId" type="string">
  Número de pasaporte o identificación nacional actualizado.
</ParamField>

### Respuesta

```json
{ "message": "Perfil actualizado exitosamente" }
```

## Uso del token

Incluye el token devuelto por el registro o inicio de sesión en cada solicitud a un endpoint protegido:

```text
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

El frontend almacena el token en `localStorage` y la utilidad `apiClient` lo adjunta automáticamente. Al construir tu propio cliente, recupera el token tras el inicio de sesión y adjúntalo al encabezado de cada solicitud posterior.

<Note>
  Los tokens codifican `userId` y `role` en su payload y están firmados con la variable de entorno `JWT_SECRET`. Siempre establece un `JWT_SECRET` fuerte y único en producción — nunca uses el valor predeterminado incluido en el repositorio.
</Note>

## Respuestas de error

| Estado HTTP | Condición |
| --- | --- |
| `400 Bad Request` | Validación fallida (ej. campo obligatorio faltante, correo electrónico ya registrado) |
| `401 Unauthorized` | Token ausente, expirado o con firma inválida — el cliente debe volver a autenticarse |
| `403 Forbidden` | El token es válido pero el rol del usuario no tiene permiso para el recurso solicitado |
| `404 Not Found` | El usuario referenciado por el token ya no existe en la base de datos |

Cuando se devuelve un `401` en una ruta protegida, descarta el token almacenado y redirige al usuario a la pantalla de inicio de sesión. Un `403` significa que el endpoint requiere un rol superior (`staff` o `admin`) al que tiene el usuario actual.
