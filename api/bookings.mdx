---
title: "Bookings API — Crear y Gestionar Reservas"
description: "Referencia para los endpoints de reservas de ViniHotel: crear reservas, ver historial, actualizar estado, cancelar estadías y listar todas las reservas para personal y administradores."
---

La Bookings API gestiona el ciclo de vida completo de las reservas en ViniHotel. Los huéspedes pueden crear reservas sin autenticación, pero deben autenticarse para ver su historial de reservas. Antes de crear una reserva, el servidor llama automáticamente a la verificación de disponibilidad para evitar reservas duplicadas y violaciones de capacidad.

<Note>
  Los endpoints protegidos requieren un header `Authorization: Bearer <token>`. El token se obtiene desde el endpoint `/api/auth/login`.
</Note>

---

## GET /api/bookings/my-bookings

Devuelve todas las reservas del usuario autenticado actualmente. Requiere autenticación.

El servidor resuelve el `idCliente` del usuario que realiza la llamada desde el JWT y devuelve únicamente sus reservas, combinadas con detalles de habitación y hotel.

### Headers

<ParamField header="Authorization" type="string" required>
  `Bearer <token>` — JWT obtenido al iniciar sesión.
</ParamField>

### Respuesta

<ResponseField name="[]" type="object[]">
  Array de objetos reserva del usuario autenticado.

  <Expandable title="propiedades del objeto reserva">
    <ResponseField name="id" type="string" required>
      UUID de la reserva.
    </ResponseField>

    <ResponseField name="roomId" type="string" required>
      UUID de la habitación reservada.
    </ResponseField>

    <ResponseField name="idCliente" type="integer" required>
      ID del cliente que realizó la reserva.
    </ResponseField>

    <ResponseField name="checkIn" type="string" required>
      Fecha de check-in en formato `YYYY-MM-DD`.
    </ResponseField>

    <ResponseField name="checkOut" type="string" required>
      Fecha de check-out en formato `YYYY-MM-DD`.
    </ResponseField>

    <ResponseField name="numberOfGuests" type="integer" required>
      Número de huéspedes en la reserva.
    </ResponseField>

    <ResponseField name="totalPrice" type="number" required>
      Precio total en USD.
    </ResponseField>

    <ResponseField name="status" type="string" required>
      Estado de la reserva: `confirmed`, `checked-in`, `checked-out`, o `cancelled`.
    </ResponseField>

    <ResponseField name="paymentStatus" type="string" required>
      Estado del pago: `pending`, `paid`, o `refunded`.
    </ResponseField>

    <ResponseField name="roomName" type="string">
      Nombre de la habitación reservada (combinado).
    </ResponseField>

    <ResponseField name="type" type="string">
      Tipo de habitación (combinado).
    </ResponseField>

    <ResponseField name="price" type="number">
      Precio por noche de la habitación (combinado).
    </ResponseField>

    <ResponseField name="hotelName" type="string">
      Nombre del hotel (combinado).
    </ResponseField>

    <ResponseField name="location" type="string">
      Ubicación del hotel (combinado).
    </ResponseField>
  </Expandable>
</ResponseField>

### Ejemplo

```bash
curl http://localhost:5000/api/bookings/my-bookings \
  -H "Authorization: Bearer <token>"
```

```json
    "roomId": "room-uuid-abcd",
    "idCliente": 7,
    "checkIn": "2026-05-01",
    "checkOut": "2026-05-05",
    "numberOfGuests": 2,
    "totalPrice": 720.00,
    "status": "confirmed",
    "paymentStatus": "pending",
    "roomName": "Deluxe Double",
    "type": "deluxe",
    "price": 180.00,
    "hotelName": "Hotel Vini Grand",
    "location": "Downtown, Caracas"
  }
]
```

## POST /api/bookings

Crea una nueva reserva. La autenticación es opcional — si hay un JWT válido presente, la reserva se vincula al `idCliente` del usuario autenticado; de lo contrario, `idCliente` se almacena como `null`.

El servidor verifica la disponibilidad antes de insertar el registro. Si la habitación no está disponible (status incorrecto, exceso de capacidad o fechas superpuestas), la solicitud se rechaza con `400`.

<Note>
  Si `paymentMethod` es `"debit-card"`, el `paymentStatus` se establece automáticamente en `"paid"` independientemente del campo `paymentStatus` en el body de la solicitud.
</Note>

### Parámetros del body

<ParamField body="roomId" type="string" required>
  UUID de la habitación a reservar.
</ParamField>

<ParamField body="checkIn" type="string" required>
  Fecha de check-in en formato `YYYY-MM-DD`.
</ParamField>

<ParamField body="checkOut" type="string" required>
  Fecha de check-out en formato `YYYY-MM-DD`.
</ParamField>

<ParamField body="guests" type="integer" required>
  Número de huéspedes. No debe superar la `capacity` de la habitación.
</ParamField>

<ParamField body="guestName" type="string" required>
  Nombre completo del huésped principal.
</ParamField>

<ParamField body="guestEmail" type="string" required>
  Correo electrónico del huésped principal.
</ParamField>

<ParamField body="totalPrice" type="number" required>
  Precio total en USD por la estadía.
</ParamField>

<ParamField body="paymentMethod" type="string" required>
  Método de pago. Uno de: `credit_card`, `debit-card`, `paypal`, `twallet`.
</ParamField>

<ParamField body="paymentStatus" default="pending" type="string">
  Estado de pago inicial. Por defecto es `"pending"`. Se sobreescribe a `"paid"` cuando `paymentMethod` es `"debit-card"`.
</ParamField>

### Respuesta

<ResponseField name="message" type="string" required>
  Confirmación: `"Reserva creada exitosamente"`.
</ResponseField>

<ResponseField name="id" type="string" required>
  UUID de la reserva recién creada.
</ResponseField>

<ResponseField name="bookingId" type="string" required>
  Igual que `id`. Proporcionado por conveniencia.
</ResponseField>

<ResponseField name="paymentStatus" type="string" required>
  Estado de pago final tras el procesamiento: `"pending"` o `"paid"`.
</ResponseField>

### Ejemplo

```bash
curl -X POST http://localhost:5000/api/bookings \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{
    "roomId": "room-uuid-abcd",
    "checkIn": "2026-05-01",
    "checkOut": "2026-05-05",
    "guests": 2,
    "guestName": "Maria Lopez",
    "guestEmail": "maria@example.com",
    "totalPrice": 720.00,
    "paymentMethod": "credit_card"
  }'
```

```json
{
  "message": "Reserva creada exitosamente",
  "id": "booking-uuid-1234",
  "bookingId": "booking-uuid-1234",
  "paymentStatus": "pending"
}
```

## PUT /api/bookings/:id

Actualiza el estado o el estado de pago de una reserva. Requiere autenticación.

### Parámetros de ruta

<ParamField path="id" type="string" required>
  UUID de la reserva a actualizar.
</ParamField>

### Parámetros del body

<ParamField body="status" type="string">
  Nuevo estado de la reserva. Uno de: `confirmed`, `checked-in`, `checked-out`, `cancelled`.
</ParamField>

<ParamField body="paymentStatus" type="string">
  Nuevo estado de pago. Uno de: `pending`, `paid`, `refunded`.
</ParamField>

<ParamField body="totalPrice" type="number">
  Precio total actualizado en USD si el monto de la reserva cambia.
</ParamField>

<Note>
  Solo `status`, `paymentStatus` y `totalPrice` son actualizables mediante este endpoint. Los demás campos de la reserva (habitación, fechas, huéspedes) no pueden modificarse después de la creación.
</Note>

### Respuesta

<ResponseField name="message" type="string" required>
  Confirmación: `"Reserva actualizada exitosamente"`.
</ResponseField>

### Ejemplo

```bash
curl -X PUT http://localhost:5000/api/bookings/booking-uuid-1234 \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{"status": "checked-in", "paymentStatus": "paid"}'
```

```json
{
  "message": "Reserva actualizada exitosamente"
}
```

## POST /api/bookings/:id/cancel

Cancela una reserva estableciendo su `status` en `"cancelled"` y `paymentStatus` en `"refunded"`. Requiere autenticación.

<Note>
  La cancelación establece automáticamente `paymentStatus` en `"refunded"`. No se necesita body adicional en la solicitud.
</Note>

### Parámetros de ruta

<ParamField path="id" type="string" required>
  UUID de la reserva a cancelar.
</ParamField>

### Respuesta

<ResponseField name="message" type="string" required>
  Confirmación: `"Reserva cancelada exitosamente"`.
</ResponseField>

### Ejemplo

```bash
curl -X POST http://localhost:5000/api/bookings/booking-uuid-1234/cancel \
  -H "Authorization: Bearer <token>"
```

```json
{
  "message": "Reserva cancelada exitosamente"
}
```

## Estados de reserva

| Estado | Descripción |
| --- | --- |
| `confirmed` | Reserva creada y aceptada. Por defecto al crear. |
| `checked-in` | El huésped ha llegado al hotel. |
| `checked-out` | El huésped ha completado su estadía. |
| `cancelled` | La reserva fue cancelada; el pago se establece en `refunded`. |

## Estados de pago

| Estado | Descripción |
| --- | --- |
| `pending` | El pago aún no ha sido cobrado. Por defecto. |
| `paid` | Pago recibido. Se establece automáticamente para reservas con `debit-card`. |
| `refunded` | Pago devuelto al huésped. Se establece automáticamente al cancelar. |

## Métodos de pago

| Valor | Descripción |
| --- | --- |
| `credit_card` | Tarjeta de crédito. El estado de pago permanece en `pending` hasta actualizarse manualmente. |
| `debit-card` | Tarjeta de débito. El estado de pago se establece automáticamente en `paid` al crear la reserva. |
| `paypal` | PayPal. El estado de pago permanece en `pending`. |
| `twallet` | Pago digital T-Wallet. El estado de pago permanece en `pending`. |

<Note>
  El valor `debit-card` usa un guion, no un guion bajo. Usar `paymentMethod: "debit-card"` es la única forma de tener el `paymentStatus` de la reserva establecido automáticamente en `"paid"` al momento de la creación.
</Note>
