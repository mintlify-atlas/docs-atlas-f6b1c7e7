---
title: "Bookings API — Create and Manage Reservations"
description: "Reference for ViniHotel booking endpoints: create reservations, view history, update status, cancel stays, and list all bookings for staff and admins."
---

The Bookings API handles the full reservation lifecycle in ViniHotel. Guests can create bookings without authentication but must authenticate to view their booking history. Before creating a booking the server automatically calls the availability check to prevent double-booking and capacity violations.

<Note>
  Protected endpoints require an `Authorization: Bearer <token>` header. The token is obtained from the `/api/auth/login` endpoint.
</Note>

---

## GET /api/bookings/my-bookings

Returns all bookings for the currently authenticated user. Requires authentication.

The server resolves the calling user's `idCliente` from the JWT and returns only their bookings, joined with room and hotel details.

### Headers

<ParamField header="Authorization" type="string" required>
  `Bearer <token>` — JWT obtained on login.
</ParamField>

### Response

<ResponseField name="[]" type="object[]">
  Array of booking objects for the authenticated user.
  <Expandable title="booking object properties">
    <ResponseField name="id" type="string" required>
      UUID of the booking.
    </ResponseField>
    <ResponseField name="roomId" type="string" required>
      UUID of the reserved room.
    </ResponseField>
    <ResponseField name="idCliente" type="integer" required>
      ID of the client who made the booking.
    </ResponseField>
    <ResponseField name="checkIn" type="string" required>
      Check-in date in `YYYY-MM-DD` format.
    </ResponseField>
    <ResponseField name="checkOut" type="string" required>
      Check-out date in `YYYY-MM-DD` format.
    </ResponseField>
    <ResponseField name="numberOfGuests" type="integer" required>
      Number of guests in the reservation.
    </ResponseField>
    <ResponseField name="totalPrice" type="number" required>
      Total price in USD.
    </ResponseField>
    <ResponseField name="status" type="string" required>
      Booking status: `confirmed`, `checked-in`, `checked-out`, or `cancelled`.
    </ResponseField>
    <ResponseField name="paymentStatus" type="string" required>
      Payment status: `pending`, `paid`, or `refunded`.
    </ResponseField>
    <ResponseField name="roomName" type="string">
      Name of the reserved room (joined).
    </ResponseField>
    <ResponseField name="type" type="string">
      Room type (joined).
    </ResponseField>
    <ResponseField name="price" type="number">
      Room's per-night price (joined).
    </ResponseField>
    <ResponseField name="hotelName" type="string">
      Name of the hotel (joined).
    </ResponseField>
    <ResponseField name="location" type="string">
      Hotel location (joined).
    </ResponseField>
  </Expandable>
</ResponseField>

### Example

```bash
curl http://localhost:5000/api/bookings/my-bookings \
  -H "Authorization: Bearer <token>"
```

```json
[
  {
    "id": "booking-uuid-1234",
    "roomId": "room-uuid-abcd",
    "idCliente": 7,
    "checkIn": "2026-05-01",
    "checkOut": "2026-05-05",
    "numberOfGuests": 2,
    "totalPrice": 720.00,
    "status": "confirmed",
    "paymentStatus": "pending",
    "roomName": "Deluxe Double",
    "type": "deluxe",
    "price": 180.00,
    "hotelName": "Hotel Vini Grand",
    "location": "Downtown, Caracas"
  }
]
```

## POST /api/bookings

Creates a new booking. Authentication is optional — if a valid JWT is present the booking is linked to the authenticated user's `idCliente`; otherwise `idCliente` is stored as `null`.

The server checks availability before inserting the record. If the room is unavailable (wrong status, over capacity, or overlapping dates), the request is rejected with `400`.

<Note>
  If `paymentMethod` is `"debit-card"`, the `paymentStatus` is automatically set to `"paid"` regardless of the `paymentStatus` field in the request body.
</Note>

### Body parameters

<ParamField body="roomId" type="string" required>
  UUID of the room to reserve.
</ParamField>
<ParamField body="checkIn" type="string" required>
  Check-in date in `YYYY-MM-DD` format.
</ParamField>
<ParamField body="checkOut" type="string" required>
  Check-out date in `YYYY-MM-DD` format.
</ParamField>
<ParamField body="guests" type="integer" required>
  Number of guests. Must not exceed the room's `capacity`.
</ParamField>
<ParamField body="guestName" type="string" required>
  Full name of the primary guest.
</ParamField>
<ParamField body="guestEmail" type="string" required>
  Email address of the primary guest.
</ParamField>
<ParamField body="totalPrice" type="number" required>
  Total price in USD for the stay.
</ParamField>
<ParamField body="paymentMethod" type="string" required>
  Payment method. One of: `credit_card`, `debit-card`, `paypal`, `twallet`.
</ParamField>
<ParamField body="paymentStatus" type="string" default="pending">
  Initial payment status. Defaults to `"pending"`. Overridden to `"paid"` when `paymentMethod` is `"debit-card"`.
</ParamField>

### Response

<ResponseField name="message" type="string" required>
  Confirmation: `"Reserva creada exitosamente"`.
</ResponseField>
<ResponseField name="id" type="string" required>
  UUID of the newly created booking.
</ResponseField>
<ResponseField name="bookingId" type="string" required>
  Same as `id`. Provided for convenience.
</ResponseField>
<ResponseField name="paymentStatus" type="string" required>
  Final payment status after processing: `"pending"` or `"paid"`.
</ResponseField>

### Example

```bash
curl -X POST http://localhost:5000/api/bookings \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{
    "roomId": "room-uuid-abcd",
    "checkIn": "2026-05-01",
    "checkOut": "2026-05-05",
    "guests": 2,
    "guestName": "Maria Lopez",
    "guestEmail": "maria@example.com",
    "totalPrice": 720.00,
    "paymentMethod": "credit_card"
  }'
```

```json
{
  "message": "Reserva creada exitosamente",
  "id": "booking-uuid-1234",
  "bookingId": "booking-uuid-1234",
  "paymentStatus": "pending"
}
```

## PUT /api/bookings/:id

Updates the status or payment status of a booking. Requires authentication.

### Path parameters

<ParamField path="id" type="string" required>
  UUID of the booking to update.
</ParamField>

### Body parameters

<ParamField body="status" type="string">
  New booking status. One of: `confirmed`, `checked-in`, `checked-out`, `cancelled`.
</ParamField>
<ParamField body="paymentStatus" type="string">
  New payment status. One of: `pending`, `paid`, `refunded`.
</ParamField>
<ParamField body="totalPrice" type="number">
  Updated total price in USD if the booking amount changes.
</ParamField>

<Note>
  Only `status`, `paymentStatus`, and `totalPrice` are updatable via this endpoint. Other booking fields (room, dates, guests) cannot be changed after creation.
</Note>

### Response

<ResponseField name="message" type="string" required>
  Confirmation: `"Reserva actualizada exitosamente"`.
</ResponseField>

### Example

```bash
curl -X PUT http://localhost:5000/api/bookings/booking-uuid-1234 \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <token>" \
  -d '{"status": "checked-in", "paymentStatus": "paid"}'
```

```json
{
  "message": "Reserva actualizada exitosamente"
}
```

## POST /api/bookings/:id/cancel

Cancels a booking by setting its `status` to `"cancelled"` and `paymentStatus` to `"refunded"`. Requires authentication.

<Note>
  Cancellation automatically sets `paymentStatus` to `"refunded"`. No additional request body is needed.
</Note>

### Path parameters

<ParamField path="id" type="string" required>
  UUID of the booking to cancel.
</ParamField>

### Response

<ResponseField name="message" type="string" required>
  Confirmation: `"Reserva cancelada exitosamente"`.
</ResponseField>

### Example

```bash
curl -X POST http://localhost:5000/api/bookings/booking-uuid-1234/cancel \
  -H "Authorization: Bearer <token>"
```

```json
{
  "message": "Reserva cancelada exitosamente"
}
```

## Booking statuses

| Status | Description |
|--------|-------------|
| `confirmed` | Booking created and accepted. Default on creation. |
| `checked-in` | Guest has arrived at the hotel. |
| `checked-out` | Guest has completed their stay. |
| `cancelled` | Booking was cancelled; payment set to `refunded`. |

## Payment statuses

| Status | Description |
|--------|-------------|
| `pending` | Payment has not been collected yet. Default. |
| `paid` | Payment received. Auto-set for `debit-card` bookings. |
| `refunded` | Payment returned to guest. Set automatically on cancellation. |

## Payment methods

| Value | Description |
|-------|-------------|
| `credit_card` | Credit card. Payment status stays `pending` until manually updated. |
| `debit-card` | Debit card. Payment status is automatically set to `paid` on booking creation. |
| `paypal` | PayPal. Payment status stays `pending`. |
| `twallet` | T-Wallet digital payment. Payment status stays `pending`. |

<Note>
  The `debit-card` value uses a hyphen, not an underscore. Using `paymentMethod: "debit-card"` is the only way to have the booking's `paymentStatus` automatically set to `"paid"` at creation time.
</Note>
