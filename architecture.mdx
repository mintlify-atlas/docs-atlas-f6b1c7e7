ViniHotel es una aplicación full-stack desacoplada. El frontend React corre como servidor de desarrollo Vite en el puerto 5173 y se comunica con el backend Express en el puerto 5000 a través de HTTP. El backend persiste todos los datos en un archivo de base de datos SQLite que se crea automáticamente en `backend/data/vinihotel.db` al primer inicio. No existe un proceso compartido — los dos servicios se inician de forma independiente y se conectan únicamente mediante HTTP y un secreto JWT compartido.

## Diagrama de arquitectura

```text
┌─────────────────────────┐
│   React Frontend :5173  │  (Vite + React Router 7)
│   src/utils/apiClient   │
└────────────┬────────────┘
             │  HTTP  (Authorization: Bearer <token>)
             ▼
┌─────────────────────────┐
│   Express API :5000     │  (Node.js + Express 4)
│   /api/*                │
└────────────┬────────────┘
             │  SQL  (sqlite / sqlite3)
             ▼
┌─────────────────────────┐
│   SQLite Database       │  backend/data/vinihotel.db
│   7 tables              │
└─────────────────────────┘
```

## Estructura del frontend

El código fuente del frontend vive bajo `src/` en la raíz del proyecto.

```text
src/
├── main.tsx                  # Punto de entrada — monta <App /> en #root
├── app/
│   ├── App.tsx               # Componente raíz, provee RouterProvider
│   ├── routes.tsx            # Todas las definiciones de rutas (createBrowserRouter)
│   ├── pages/                # Un archivo por componente de página
│   │   ├── home.tsx
│   │   ├── hotel-detail.tsx
│   │   ├── payment.tsx
│   │   ├── booking-confirmation.tsx
│   │   ├── my-bookings.tsx
│   │   ├── user-profile.tsx
│   │   ├── staff-management.tsx
│   │   ├── hotel-management.tsx
│   │   ├── login.tsx
│   │   ├── register.tsx
│   │   ├── not-found.tsx
│   │   └── staff/
│   │       ├── booking-management.tsx
│   │       ├── housekeeping.tsx
│   │       └── reports.tsx
│   ├── components/
│   │   └── protected-route.tsx  # Guard de rutas basado en roles
│   └── context/              # Proveedores de contexto React (estado de auth, etc.)
└── utils/
    └── apiClient.ts          # Cliente HTTP tipado (clase ApiClient)
```

`src/utils/apiClient.ts` exporta una instancia singleton `apiClient`. Lee el JWT desde `localStorage` en la construcción y adjunta `Authorization: Bearer <token>` a cada solicitud que requiere autenticación.

## Estructura del backend

El código fuente del backend vive bajo `backend/src/`.

```text
backend/
├── src/
│   ├── server.js             # App Express, middleware, montaje de rutas, inicio
│   ├── routes/               # Routers Express (un archivo por recurso)
│   │   ├── auth.js
│   │   ├── hotels.js
│   │   ├── rooms.js
│   │   ├── bookings.js
│   │   └── invoices.js
│   ├── models/               # Funciones de consulta SQLite (un archivo por tabla)
│   │   ├── userModel.js
│   │   ├── hotelModel.js
│   │   └── roomModel.js
│   ├── middleware/
│   │   └── auth.js           # Middleware de verificación JWT + manejador de errores
│   └── utils/
│       ├── database.js       # initializeDatabase() — crea las tablas al inicio
│       └── sampleData.js     # Datos semilla para usuarios, hoteles y habitaciones
├── data/
│   └── vinihotel.db          # Archivo de base de datos SQLite (creado automáticamente)
├── package.json
└── .env                      # Variables de entorno (no incluido en el repositorio)
```

## Rutas del frontend

Todas las rutas están definidas en `src/app/routes.tsx` usando `createBrowserRouter` de React Router 7. Las rutas dentro del padre `/` se renderizan dentro del componente de layout `Root`. Las rutas protegidas usan el wrapper `ProtectedRoute`, que verifica el rol requerido antes de renderizar la página.

| Ruta | Componente | Rol requerido |
| --- | --- | --- |
| `/login` | `Login` | Ninguno (público) |
| `/register` | `Register` | Ninguno (público) |
| `/` | `Home` | Ninguno (público) |
| `/hotel/:id` | `HotelDetail` | Cualquier usuario autenticado |
| `/payment` | `Payment` | Cualquier usuario autenticado |
| `/booking-confirmation` | `BookingConfirmation` | Cualquier usuario autenticado |
| `/my-bookings` | `MyBookings` | Cualquier usuario autenticado |
| `/profile` | `UserProfile` | Cualquier usuario autenticado |
| `/bookings` | `BookingManagement` | `staff` o `admin` |
| `/housekeeping` | `Housekeeping` | `staff` o `admin` |
| `/staff` | `StaffManagement` | Solo `admin` |
| `/hotels` | `HotelManagement` | Solo `admin` |
| `/reports` | `Reports` | Solo `admin` |

<Note>
  La verificación de roles ocurre en el lado del cliente dentro de `ProtectedRoute` y nuevamente en el servidor dentro del middleware JWT de Express. Un bypass en el lado del cliente igualmente resultará en un 401 o 403 desde la API.
</Note>

## URLs base de la API

| Servicio | URL base | Notas |
| --- | --- | --- |
| Raíz del backend | `http://localhost:5000` | Configurable via `PORT` en `.env` |
| Prefijo de API | `http://localhost:5000/api` | Todos los endpoints están bajo `/api` |
| Health check | `http://localhost:5000/api/health` | Retorna `{ "status": "Backend running" }` |
| Frontend | `http://localhost:5173` | Configurable en Vite; debe coincidir con `CORS_ORIGIN` |

La clase `ApiClient` en `src/utils/apiClient.ts` tiene `http://localhost:5000/api` como URL base definida en el código. Para apuntar a un backend diferente, actualiza la constante `API_URL` en ese archivo.

## Flujo de autenticación

ViniHotel utiliza autenticación JWT sin estado con una duración de token de 7 días.

<Steps>
  <Step title="Login o registro">
    El frontend llama a `POST /api/auth/login` (o `/api/auth/register`) con el correo electrónico y contraseña del usuario (campo `contrasena`).
  </Step>
  <Step title="Token emitido">
    El backend verifica la contraseña con bcrypt, firma un JWT usando `JWT_SECRET` y retorna el token en el cuerpo de la respuesta.
  </Step>
  <Step title="Token almacenado">
    `ApiClient.setToken()` guarda el token en `localStorage` bajo la clave `token`. En cargas de página subsiguientes, el constructor lo recupera con `localStorage.getItem('token')`.
  </Step>
  <Step title="Solicitudes autenticadas">
    Cada llamada a la API realizada a través de `apiClient` incluye automáticamente el encabezado:

    ```text
    Authorization: Bearer <token>
    ```
  </Step>
  <Step title="Expiración del token">
    Los tokens expiran después de 7 días (`JWT_EXPIRE=7d`). Para cerrar sesión, llama a `ApiClient.clearToken()`, que elimina el token de `localStorage`.
  </Step>
</Steps>
