ViniHotel usa SQLite3 como base de datos, almacenada en `backend/data/vinihotel.db`. El archivo y su directorio padre se crean automáticamente la primera vez que arranca el servidor — nunca necesitas crearlos manualmente. Todas las definiciones de tablas viven en `backend/src/utils/database.js` y se aplican mediante sentencias `CREATE TABLE IF NOT EXISTS` dentro de la función `initializeDatabase()` que se llama al iniciar el servidor.

## Ubicación de la base de datos

```text
backend/
└── data/
    └── vinihotel.db   ← archivo SQLite, creado automáticamente en la primera ejecución
```

<Note>
  Para inspeccionar la base de datos directamente, usa [DB Browser for SQLite](https://sqlitebrowser.org/), la extensión "SQLite" de VS Code (`ms-vscode.sqlite`), o la herramienta de línea de comandos: `sqlite3 backend/data/vinihotel.db`.
</Note>

## Tablas

### usuarios

Almacena todas las cuentas de usuario — clientes, miembros del personal y administradores.

| Columna | Tipo | Restricción | Descripción |
| --- | --- | --- | --- |
| `idUsuario` | INTEGER | PK, AUTOINCREMENT | ID único de usuario |
| `nombre` | TEXT | NOT NULL | Nombre |
| `apellido` | TEXT | NOT NULL | Apellido |
| `email` | TEXT | NOT NULL, UNIQUE | Correo de inicio de sesión |
| `contrasena` | TEXT | NOT NULL | Contraseña hasheada con bcrypt |
| `rol` | TEXT | DEFAULT `'client'` | `client` / `staff` / `admin` |
| `phone` | TEXT | — | Número de teléfono de contacto |
| `address` | TEXT | — | Dirección |
| `dateOfBirth` | DATE | — | Fecha de nacimiento |
| `nationality` | TEXT | — | Nacionalidad |
| `documentId` | TEXT | — | Número de pasaporte o identificación |
| `createdAt` | DATETIME | DEFAULT NOW | Hora de creación del registro |
| `updatedAt` | DATETIME | DEFAULT NOW | Hora de última actualización |

---

### clientes

Contiene datos de perfil específicos del cliente en una relación uno a uno con `usuarios`.

| Columna | Tipo | Restricción | Descripción |
| --- | --- | --- | --- |
| `idCliente` | INTEGER | PK, AUTOINCREMENT | ID único de cliente |
| `telefono` | TEXT | — | Número de teléfono del cliente |
| `documentoIdentidad` | TEXT | — | Documento de identidad |
| `idUsuario` | INTEGER | FK, UNIQUE | Referencia a `usuarios(idUsuario)` |
| `createdAt` | DATETIME | DEFAULT NOW | Hora de creación del registro |
| `updatedAt` | DATETIME | DEFAULT NOW | Hora de última actualización |

Eliminar una fila de `usuarios` elimina en cascada la fila vinculada de `clientes` automáticamente (`ON DELETE CASCADE`).

---

### hoteles

Almacena los listados de hoteles.

| Columna | Tipo | Restricción | Descripción |
| --- | --- | --- | --- |
| `idHotel` | TEXT | PK | UUID |
| `nombre` | TEXT | NOT NULL | Nombre del hotel |
| `description` | TEXT | NOT NULL | Descripción completa |
| `location` | TEXT | NOT NULL | Ubicación geográfica |
| `image` | TEXT | NOT NULL | URL de la imagen principal |
| `rating` | REAL | NOT NULL | Calificación de 0 a 5 |
| `amenities` | TEXT | NOT NULL | Array JSON de servicios |
| `createdAt` | DATETIME | DEFAULT NOW | Hora de creación del registro |
| `updatedAt` | DATETIME | DEFAULT NOW | Hora de última actualización |

El campo `amenities` se almacena como array JSON:

```json
["WiFi", "Piscina", "Gym", "Spa", "Restaurante 24/7", "Servicio de habitaciones"]
```

### rooms

Habitaciones del hotel, cada una perteneciente a un hotel.

| Columna | Tipo | Restricción | Descripción |
| --- | --- | --- | --- |
| `id` | TEXT | PK | UUID |
| `hotelId` | TEXT | FK NOT NULL | Referencia a `hoteles(idHotel)` |
| `name` | TEXT | NOT NULL | Nombre de la habitación (ej. Suite Presidencial) |
| `type` | TEXT | NOT NULL | `standard` / `deluxe` / `suite` / etc. |
| `price` | REAL | NOT NULL | Precio por noche en USD |
| `capacity` | INTEGER | NOT NULL | Número máximo de huéspedes |
| `image` | TEXT | NOT NULL | URL de la imagen de la habitación |
| `amenities` | TEXT | NOT NULL | Array JSON de servicios de la habitación |
| `available` | INTEGER | DEFAULT `1` | Número de unidades disponibles (stock) |
| `status` | TEXT | DEFAULT `'available'` | `available` / `occupied` / `maintenance` / `cleaning` / `unavailable` |
| `createdAt` | DATETIME | DEFAULT NOW | Hora de creación del registro |
| `updatedAt` | DATETIME | DEFAULT NOW | Hora de última actualización |

---

### bookings

Registros de reservas que vinculan una habitación con un cliente.

| Columna | Tipo | Restricción | Descripción |
| --- | --- | --- | --- |
| `id` | TEXT | PK | UUID |
| `roomId` | TEXT | FK NOT NULL | Referencia a `rooms(id)` |
| `idCliente` | INTEGER | FK NOT NULL | Referencia a `clientes(idCliente)` |
| `checkIn` | DATE | NOT NULL | Fecha de entrada |
| `checkOut` | DATE | NOT NULL | Fecha de salida |
| `guests` | INTEGER | NOT NULL | Número de huéspedes |
| `totalPrice` | REAL | NOT NULL | Precio total en USD |
| `paymentMethod` | TEXT | NOT NULL | `credit_card` / `debit-card` / `paypal` / `twallet` |
| `status` | TEXT | DEFAULT `'confirmed'` | `confirmed` / `checked-in` / `checked-out` / `cancelled` |
| `paymentStatus` | TEXT | DEFAULT `'pending'` | `pending` / `paid` / `refunded` |
| `createdAt` | DATETIME | DEFAULT NOW | Hora de creación del registro |
| `updatedAt` | DATETIME | DEFAULT NOW | Hora de última actualización |

---

### invoices

Facturas de pago asociadas a las reservas.

| Columna | Tipo | Restricción | Descripción |
| --- | --- | --- | --- |
| `id` | TEXT | PK | UUID |
| `bookingId` | TEXT | FK NOT NULL | Referencia a `bookings(id)` |
| `userId` | INTEGER | FK NOT NULL | Referencia a `usuarios(idUsuario)` |
| `subtotal` | REAL | NOT NULL | Monto antes de impuestos |
| `taxes` | REAL | NOT NULL | Monto de impuestos |
| `total` | REAL | NOT NULL | Total final (`subtotal + taxes`) |
| `additionalCharges` | TEXT | — | Objeto JSON con cargos adicionales |
| `paymentMethod` | TEXT | NOT NULL | Método de pago utilizado |
| `paymentStatus` | TEXT | DEFAULT `'pending'` | `pending` / `paid` / `failed` / `refunded` |
| `issuedDate` | DATETIME | DEFAULT NOW | Hora de emisión de la factura |
| `createdAt` | DATETIME | DEFAULT NOW | Hora de creación del registro |
| `updatedAt` | DATETIME | DEFAULT NOW | Hora de última actualización |

El campo `additionalCharges` es un objeto JSON:

```json
{
  "resort_fee": 15.00,
  "service_charge": 20.50,
  "parking": 10.00
}
```

### staff

Miembros del personal del hotel.

| Columna | Tipo | Restricción | Descripción |
| --- | --- | --- | --- |
| `id` | TEXT | PK | UUID |
| `name` | TEXT | NOT NULL | Nombre completo |
| `position` | TEXT | NOT NULL | `receptionist` / `housekeeper` / `manager` |
| `hotelId` | TEXT | FK NOT NULL | Referencia a `hoteles(idHotel)` |
| `email` | TEXT | NOT NULL | Correo de contacto |
| `phone` | TEXT | — | Número de teléfono |
| `status` | TEXT | DEFAULT `'active'` | `active` / `inactive` / `on-leave` |
| `hireDate` | DATE | NOT NULL | Fecha de contratación |
| `idUsuario` | INTEGER | FK | Referencia a `usuarios(idUsuario)` (opcional) |
| `createdAt` | DATETIME | DEFAULT NOW | Hora de creación del registro |
| `updatedAt` | DATETIME | DEFAULT NOW | Hora de última actualización |

Un miembro del personal puede o no tener una cuenta `usuarios` vinculada.

## Relaciones entre entidades

```text
USUARIOS
  ├─ 1:1 ─────> CLIENTES
  ├─ 1:N ─────> STAFF
  └─ 1:N ─────> INVOICES

HOTELES
  ├─ 1:N ─────> ROOMS
  └─ 1:N ─────> STAFF

ROOMS
  └─ 1:N ─────> BOOKINGS

CLIENTES
  └─ 1:N ─────> BOOKINGS

BOOKINGS
  └─ 1:N ─────> INVOICES
```

Una sola reserva puede tener múltiples facturas (ej. para pagos parciales o reembolsos).

## Índices

Todos los índices son creados por `initializeDatabase()` para optimizar los patrones de join y búsqueda más comunes:

```sql
CREATE INDEX idx_rooms_hotelId       ON rooms(hotelId);
CREATE INDEX idx_clientes_idUsuario  ON clientes(idUsuario);
CREATE INDEX idx_staff_hotelId       ON staff(hotelId);
CREATE INDEX idx_bookings_roomId     ON bookings(roomId);
CREATE INDEX idx_bookings_idCliente  ON bookings(idCliente);
CREATE INDEX idx_invoices_bookingId  ON invoices(bookingId);
CREATE INDEX idx_usuarios_email      ON usuarios(email);
```

## Consultas SQL útiles

<AccordionGroup>
  <Accordion title="Ingresos por hotel">
    ```sql
    SELECT h.nombre, SUM(i.total) AS ingresos
    FROM invoices i
    JOIN bookings b  ON i.bookingId = b.id
    JOIN rooms r     ON b.roomId    = r.id
    JOIN hoteles h   ON r.hotelId   = h.idHotel
    GROUP BY h.idHotel;
    ```
  </Accordion>

  <Accordion title="Verificar disponibilidad de habitación">
    ```sql
    SELECT * FROM rooms WHERE id = 'room-uuid' AND available > 0;
    ```
  </Accordion>

  <Accordion title="Todas las reservas de un cliente">
    ```sql
    SELECT b.*
    FROM bookings b
    JOIN clientes c ON b.idCliente = c.idCliente
    WHERE c.idUsuario = 1;
    ```
  </Accordion>

  <Accordion title="Detectar reservas solapadas">
    ```sql
    SELECT * FROM bookings
    WHERE roomId = 'room-uuid'
      AND status != 'cancelled'
      AND checkIn  < '2026-05-01'
      AND checkOut > '2026-04-20';
    ```
  </Accordion>

  <Accordion title="Clientes más frecuentes">
    ```sql
    SELECT u.nombre, u.apellido, COUNT(b.id) AS reservas
    FROM bookings b
    JOIN clientes c ON b.idCliente  = c.idCliente
    JOIN usuarios u ON c.idUsuario  = u.idUsuario
    GROUP BY u.idUsuario
    ORDER BY reservas DESC
    LIMIT 10;
    ```
  </Accordion>
</AccordionGroup>

## Configuración de SQLite

La conexión de base de datos en `src/utils/database.js` aplica los siguientes PRAGMAs para fiabilidad y rendimiento:

```sql
PRAGMA foreign_keys = ON;
PRAGMA journal_mode = WAL;
PRAGMA synchronous  = NORMAL;
PRAGMA cache_size   = -64000;
PRAGMA temp_store   = MEMORY;
PRAGMA mmap_size    = 30000000;
PRAGMA page_size    = 4096;
```

También se establece un `busyTimeout` de 5000 ms para manejar la contención de escritura concurrente de forma elegante.
