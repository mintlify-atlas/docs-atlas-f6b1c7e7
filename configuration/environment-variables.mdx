title: "Referencia de Variables de Entorno"

---

El backend de ViniHotel se configura completamente a través de variables de entorno cargadas mediante `dotenv`. Crea un archivo `.env` en el directorio `backend/` antes de iniciar el servidor — la aplicación lee estos valores al arrancar mediante `dotenv.config()` en `server.js`.

## Ejemplo de archivo .env

Coloca este archivo en `backend/.env`:

```text
PORT=5000
DATABASE_PATH=./data/vinihotel.db
JWT_SECRET=your_super_secret_jwt_key_change_this
JWT_EXPIRE=7d
NODE_ENV=development
CORS_ORIGIN=http://localhost:5173
```

<Warning>
  Nunca incluyas tu archivo `.env` en el control de versiones. El `.gitignore` del backend ya lo excluye. Subir un `JWT_SECRET` real permitiría que cualquier persona falsifique tokens de autenticación para tu aplicación.
</Warning>

## Referencia de variables

<AccordionGroup>
  <Accordion title="PORT">
    **Valor predeterminado:** `5000`

    El puerto en el que escucha el servidor Express. El servidor se enlaza con:

    ```js
    const PORT = process.env.PORT || 5000;
    ```

    Cámbialo si el puerto 5000 ya está en uso en tu máquina. Si lo cambias, actualiza `CORS_ORIGIN` en el frontend en consecuencia y ajusta cualquier comando `curl` para usar el nuevo puerto.
  </Accordion>

  <Accordion title="DATABASE_PATH">
    **Valor predeterminado:** `./data/vinihotel.db`

    Ruta al archivo de la base de datos SQLite, relativa al directorio `backend/`. La función `initializeDatabase()` en `src/utils/database.js` abre o crea este archivo en la primera ejecución — no necesitas crearlo manualmente. El directorio `backend/data/` también se crea automáticamente si no existe.
  </Accordion>

  <Accordion title="JWT_SECRET">
    **Obligatorio** — no hay un valor seguro por defecto en producción.

    La clave secreta utilizada para firmar y verificar los tokens JWT en `src/middleware/auth.js`. El código usa como respaldo `'your_super_secret_jwt_key_change_this'` cuando la variable no está definida, pero este valor de respaldo es público y nunca debe usarse en producción.

    Genera un secreto robusto con:

    ```bash
    node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"
    ```
  </Accordion>

  <Accordion title="JWT_EXPIRE">
    **Valor predeterminado:** `7d`

    Controla cuánto tiempo permanecen válidos los tokens emitidos. Se pasa directamente a la opción `expiresIn` de `jsonwebtoken`:

    ```js
    jwt.sign({ userId, role }, JWT_SECRET, { expiresIn: process.env.JWT_EXPIRE || '7d' })
    ```

    Acepta cualquier valor que soporte la biblioteca `jsonwebtoken`: `60` (segundos), `'2h'`, `'30d'`, etc.
  </Accordion>

  <Accordion title="NODE_ENV">
    **Valores:** `development` | `production`

    Indicador estándar del entorno de Node.js. Establécelo en `production` al desplegar para reducir el registro detallado y habilitar el manejo de errores a nivel de producción. El middleware de errores de Express usa este valor para determinar la verbosidad de las respuestas.
  </Accordion>

  <Accordion title="CORS_ORIGIN">
    **Valor predeterminado:** `http://localhost:5173`

    La URL del frontend desde la que el backend permite solicitudes de origen cruzado. Configurado en `server.js` como:

    ```js
    const CORS_ORIGIN = process.env.CORS_ORIGIN || 'http://localhost:5173';
    app.use(cors({ origin: CORS_ORIGIN, credentials: true }));
    ```

    `http://localhost:5173` es la dirección predeterminada del servidor de desarrollo Vite. Actualiza esto a la URL de tu frontend desplegado en producción.
  </Accordion>
</AccordionGroup>

## Lista de verificación para producción

<Note>
  Los siguientes cambios son obligatorios antes de desplegar ViniHotel en cualquier entorno público.
</Note>

- **Cambia `JWT_SECRET`** por un valor criptográficamente aleatorio (64\+ bytes). Cualquiera que conozca este secreto puede emitir tokens válidos para cualquier usuario.
- **Establece `NODE_ENV=production`** para suprimir trazas de pila en las respuestas de error.
- **Actualiza `CORS_ORIGIN`** al dominio de tu frontend de producción (ej. `https://app.vinihotel.com`).
- **Usa HTTPS** para todo el tráfico. Los tokens JWT transmitidos por HTTP simple pueden ser interceptados.
- **Considera PostgreSQL** para cargas de trabajo en producción. SQLite es adecuado para desarrollo y despliegues de bajo tráfico, pero el QUICKSTART.md señala que se recomienda migrar a MySQL/PostgreSQL a escala.
