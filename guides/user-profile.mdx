Tu página de perfil en `/profile` es el lugar central para mantener tus datos personales actualizados, revisar reservas pasadas y acceder a las facturas. Los datos del perfil se almacenan en la base de datos del backend y se recuperan a través del endpoint `GET /api/auth/me` usando tu token JWT.

<Info>
  La página de perfil requiere autenticación. Los usuarios no autenticados son redirigidos a `/login`.
</Info>

## Acceder a tu perfil

Navega a `/profile` desde la navegación principal. La página está organizada en tres pestañas:

- **Datos Personales** — formulario de información personal
- **Historial de Reservas** — todas las reservas vinculadas a tu cuenta
- **Facturas** — todas las facturas vinculadas a tu cuenta

## Campos del perfil

La pestaña **Datos Personales** muestra los siguientes campos del tipo `User`:

| Campo | Descripción | Editable |
| --- | --- | --- |
| `nombre` | Nombre | Sí |
| `apellido` | Apellido | Sí |
| `email` | Correo electrónico de la cuenta | No (solo lectura) |
| `phone` | Número de teléfono | Sí |
| `dateOfBirth` | Fecha de nacimiento | Sí |
| `nationality` | Nacionalidad | Sí |
| `documentId` | Número de documento de identidad | Sí |
| `address` | Dirección completa | Sí |

El campo `email` es de solo lectura después del registro. El `rol` (rol) no puede ser cambiado por el usuario. Todos los demás campos pueden actualizarse mediante `PUT /api/auth/profile`.

## Cómo actualizar tu perfil

<Steps>
  <Step title="Abre la página de perfil">
    Navega a `/profile`. La pestaña **Datos Personales** está activa por defecto.
  </Step>
  <Step title="Entra en modo de edición">
    Haz clic en **Editar Perfil**. Todos los campos editables se convierten en entradas activas.
  </Step>
  <Step title="Realiza tus cambios">
    Actualiza cualquier combinación de `nombre`, `apellido`, `phone`, `dateOfBirth`, `nationality`, `documentId` o `address`.
  </Step>
  <Step title="Guarda">
    Haz clic en **Guardar Cambios**. Los cambios se envían a `PUT /api/auth/profile` y se persisten en la base de datos del backend.
  </Step>
</Steps>

## Roles de usuario

Cada cuenta tiene un campo `role`. El rol se asigna en el momento de la creación y controla el acceso a las funciones administrativas:

<CardGroup cols={3}>
  <Card title="client" icon="user">
    Rol predeterminado para todas las cuentas auto-registradas. Acceso completo a la exploración, reserva y gestión del perfil.
  </Card>

  <Card title="staff" icon="users">
    Personal del hotel. Acceso a la gestión de reservas y housekeeping además de las rutas de cliente.
  </Card>

  <Card title="admin" icon="shield">
    Administradores. Acceso completo a todas las páginas, incluyendo gestión de hoteles, gestión de personal e informes.
  </Card>
</CardGroup>

El rol (`rol`) se almacena en la tabla `usuarios` y se codifica en el token JWT. Es aplicado tanto por el componente `ProtectedRoute` del frontend como por el middleware JWT del backend.

## Pestaña de historial de reservas

La pestaña **Historial de Reservas** lista todas las reservas asociadas a tu correo electrónico. Cada entrada muestra:

- `hotelName` y `roomName`
- Fechas de `checkIn` y `checkOut`
- Cantidad de `guests`
- `totalPrice`
- Insignia de `status` (`confirmed`, `checked-in`, `checked-out` o `cancelled`)
- Etiqueta de `paymentStatus` (`paid`, `pending` o `refunded`)

## Pestaña de facturas

La pestaña **Facturas** lista todas las facturas generadas para tus reservas. Cada tarjeta de factura muestra:

- ID de factura (últimos 8 caracteres del `id`, en mayúsculas)
- `hotelName` y `roomName`
- `issuedDate`
- Monto `total`
- Insignia de `paymentStatus`

Haz clic en **Ver Factura** para abrir un diálogo de detalle con el desglose completo del costo: `subtotal`, `taxes` (16%), `additionalCharges` y `total`. Usa **Descargar PDF** para imprimir la factura.

## Seguridad de la cuenta

<AccordionGroup>
  <Accordion title="Almacenamiento de contraseña">
    Las contraseñas se hashean con bcrypt en el backend antes de almacenarse. La contraseña en texto plano nunca se persiste. Evita reutilizar contraseñas de otros servicios.
  </Accordion>

  <Accordion title="Token de sesión">
    Después del inicio de sesión, el token JWT se almacena en `localStorage` bajo la clave `token`. El `apiClient` del frontend lee este valor al cargar y lo adjunta a cada solicitud autenticada. Borrar el almacenamiento del navegador cerrará tu sesión.
  </Accordion>

  <Accordion title="Cerrar sesión">
    Cerrar sesión llama a `apiClient.clearToken()` desde `AuthContext`, lo que elimina el token de `localStorage` y borra el estado de usuario en memoria. Serás redirigido inmediatamente fuera de cualquier ruta protegida.
  </Accordion>
</AccordionGroup>

<Note>
  Las cuentas registradas tienen el rol `client` por defecto. Las actualizaciones de rol a `staff` o `admin` requieren un cambio directo en la base de datos — no existe un cambio de rol de autoservicio en la interfaz actual.
</Note>
