ViniHotel is a full-stack hotel booking platform that lets guests browse hotels, reserve rooms, and manage their bookings — while giving hotel staff and administrators dedicated dashboards to handle operations, housekeeping, and reporting. The frontend is a React 18 single-page application built with Vite, and the backend is a Node.js + Express REST API backed by a SQLite database that is created automatically on first run.

## Tech Stack

ViniHotel is split into two independently runnable services that communicate over HTTP.

**Frontend** (`/` — root of the repository)
- React 18 with React Router 7 for client-side routing
- Vite 6 as the build tool and dev server (runs on port 5173)
- Tailwind CSS 4 for styling
- Radix UI + MUI component libraries
- `src/utils/apiClient.ts` — a typed `ApiClient` class that attaches the `Authorization: Bearer` header to every authenticated request

**Backend** (`/backend`)
- Node.js with Express 4
- SQLite via the `sqlite` and `sqlite3` packages — database file at `backend/data/vinihotel.db`
- `bcryptjs` for password hashing, `jsonwebtoken` for JWT issuance and verification
- `nodemon` for hot-reloading during development (runs on port 5000)

**Database**

The SQLite database is initialized automatically when the backend starts. It creates seven tables: `usuarios`, `clientes`, `hoteles`, `rooms`, `bookings`, `invoices`, and `staff`. Sample data (hotels, rooms, and test users) is seeded on first startup.

## User Roles

ViniHotel has three distinct roles, each with access to a different set of frontend routes and API endpoints.

| Role | Access |
|------|--------|
| `client` | Home, hotel detail, payment, booking confirmation, my bookings, profile |
| `staff` | All client pages plus booking management and housekeeping |
| `admin` | All pages including staff management, hotel management, and reports |

<Info>
  Role enforcement happens in two places: the `ProtectedRoute` component in the frontend (see `src/app/routes.tsx`) and JWT middleware on the backend. A user without the required role is redirected by the frontend before any API call is made.
</Info>
