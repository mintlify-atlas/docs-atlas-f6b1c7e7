ViniHotel es una plataforma full-stack de reservas de hoteles que permite a los huéspedes explorar hoteles, reservar habitaciones y gestionar sus reservas — al mismo tiempo que proporciona al personal del hotel y a los administradores paneles dedicados para manejar operaciones, limpieza y reportes. El frontend es una aplicación React 18 de una sola página construida con Vite, y el backend es una API REST de Node.js \+ Express respaldada por una base de datos SQLite que se crea automáticamente en la primera ejecución.

## Stack tecnológico

ViniHotel está dividido en dos servicios ejecutables de forma independiente que se comunican a través de HTTP.

**Frontend** (`/` — raíz del repositorio)

- React 18 con React Router 7 para el enrutamiento del lado del cliente
- Vite 6 como herramienta de construcción y servidor de desarrollo (se ejecuta en el puerto 5173)
- Tailwind CSS 4 para los estilos
- Librerías de componentes Radix UI \+ MUI
- `src/utils/apiClient.ts` — una clase `ApiClient` tipada que adjunta el encabezado `Authorization: Bearer` a cada solicitud autenticada

**Backend** (`/backend`)

- Node.js con Express 4
- SQLite a través de los paquetes `sqlite` y `sqlite3` — archivo de base de datos en `backend/data/vinihotel.db`
- `bcryptjs` para el hashing de contraseñas, `jsonwebtoken` para la emisión y verificación de JWT
- `nodemon` para recarga en caliente durante el desarrollo (se ejecuta en el puerto 5000)

**Base de datos**

La base de datos SQLite se inicializa automáticamente cuando el backend se inicia. Crea siete tablas: `usuarios`, `clientes`, `hoteles`, `rooms`, `bookings`, `invoices` y `staff`. Los datos de ejemplo (hoteles, habitaciones y usuarios de prueba) se cargan en la primera ejecución.

## Roles de usuario

ViniHotel tiene tres roles distintos, cada uno con acceso a un conjunto diferente de rutas del frontend y endpoints de la API.

| Rol | Acceso |
| --- | --- |
| `client` | Inicio, detalle de hotel, pago, confirmación de reserva, mis reservas, perfil |
| `staff` | Todas las páginas del cliente más gestión de reservas y limpieza |
| `admin` | Todas las páginas, incluyendo gestión de personal, gestión de hoteles y reportes |

<Info>
  La aplicación de los roles ocurre en dos lugares: el componente `ProtectedRoute` en el frontend (ver `src/app/routes.tsx`) y el middleware JWT en el backend. Un usuario sin el rol requerido es redirigido por el frontend antes de que se realice cualquier llamada a la API.
</Info>
